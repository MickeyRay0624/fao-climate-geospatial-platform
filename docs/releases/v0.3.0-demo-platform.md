# v0.3.0-demo-platform

Release date: 2026-09-01

## Outcome

This release completes the local Phase 3 demonstration platform and makes the source repository public. It preserves the original Cambodia synthetic dataset, all 13 legacy analysis runs, 1,443 legacy results and the original MinIO source object while adding governed Data Hub, native investment, Extension, governance and help workflows.

## Delivered

- Shared responsive shell, 14 development personas, capability-based routes and modular application registry.
- Governed Data Hub lifecycle, jobs, review/publish separation, immutable publication, access grants/denies, preview/download, collections, quality and lineage.
- Native administrative-boundary and normalised-indicator profiles, plus controlled WGS84 Shapefile ZIP and GeoPackage validation with derived GeoJSON representation.
- Two locally retained real-source compatibility samples (GAUL boundary and MPI table), each published with unconfirmed-licence warnings and never used to fabricate a complete ranking.
- Native investment input sets, readiness, method/scenario approval, asynchronous deterministic runs, ranking/map/contributions/comparison, output registration and historical reconciliation.
- Manual Extension Field Support across cases, observations, restricted media, assessments, verification, activities, follow-ups, supervision, knowledge approval and sync status.
- Governance administration, filtered/CSV audit, dependency/migration/scanner/backup health, nested help and a step-by-step demonstration guide.
- Clean-bootstrap, idempotent seed/backfill, database guards, backup/restore verification and automated backend/frontend/contract/browser coverage.

## Evidence boundaries

- The GAUL/MPI items are real-source samples retained in the local governed environment. Their licences are `UNCONFIRMED-SOURCE-LICENCE`; raw or derived files are intentionally absent from the public Git history.
- All runnable investment inputs, scores, ranks and map results are synthetic demonstration evidence.
- Extension cases, locations, knowledge and field events are fictional demonstration records.
- Development identities and scanner bypass are visible. The scanner state is a warning and is not production acceptance.

## Upgrade and verify

Back up database and object evidence first, then:

```bash
docker compose up --build -d
docker compose run --rm migrate alembic current
docker compose run --rm seed
python3 scripts/demo_smoke.py
```

Expected Alembic head is `20260901_0005`. Never use Compose volume deletion as an upgrade or reset mechanism.
